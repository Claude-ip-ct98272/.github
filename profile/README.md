<p>买线路的时候，销售页面上通常只有三行字：地区、类型、价格。真正决定「各账号会不会被平台串起来判定」的参数，往往要追问才给。这篇按说明书的方式，把一号一环境相关的参数分成四组——出口、会话、地区语言、容量并发，逐个说明含义、常见取值、影响范围和验证方法。看完你可以拿它当验收清单，逐项问服务商要数字，也可以用来核对自己现有配置有没有漏项。</p>

<h2>一、先分清硬参数和软参数</h2>
<p>硬参数是能测出来的，比如出口 ASN、延迟、IP 变更次数；软参数是服务商承诺的，比如独占性、售后响应、带宽上限。硬参数自己验，软参数写进合同。两类都不能只听介绍，区别在验证方式。</p>
<p>还有一类常被忽略：环境侧参数，包括用户数据目录是否独立、Cookie 作用域是否隔离、时区与语言怎么设。这些不属于线路，但直接决定「串不串」。采购前把线路参数和环境参数放在同一张表里看，才能判断整套方案是否完整。</p>

<h3>参数之间的耦合关系</h3>
<p>参数不是孤立的。比如出口在国家 A，时区就必须是 A 的时区，语言也应当是当地常用语言；会话保持时长越长，对出口稳定性的要求越高；并发数越大，共享出口被同段其他用户影响的概率越高。看单个参数没意义，要看组合起来是否自洽。</p>

<h2>二、出口类参数</h2>
<p>这一组决定「你是谁、从哪来」。四项最关键：ASN 归属、IP 类型、出口存活策略、同段复用情况。</p>

<h3>ASN 归属与 IP 类型</h3>
<p>ASN 归属看组织名是不是本地宽带运营商，出现 hosting、datacenter、cloud 就说明是机房段。IP 类型看标注，常见有 ISP、residential、business 几种。验证入口用 ipinfo.io 加另一家交叉查询，两边结论一致才可信。这一项不通过，其他参数都不用看了。</p>

<h3>出口存活策略</h3>
<p>要问清三件事：IP 是固定分配还是到期轮换、轮换周期多长、可否提前查询即将变更。参考口径是固定分配或者 24 小时内变更不超过一次。动态家宽本身是正常的，问题在于变更不可预期——你不知道什么时候变，就没法判断异常是变更引起的还是别的原因。</p>

<h2>三、会话类参数</h2>
<p>会话参数决定「一条连接能撑多久」。包括会话保持模式、超时时间、重拨行为、以及切换策略。</p>

<h3>会话保持与超时</h3>
<p>会话保持分两种：粘性会话（同一个客户端固定走同一出口）和轮换会话（每次请求或每隔一段时间换出口）。长期挂机的场景必须用粘性，轮换会让同一个号在几分钟内跨多个出口。超时时间指空闲多久断开，参考值 10–30 分钟，太短会导致频繁重连，太长会占用连接数。</p>

<h3>重拨与切换行为</h3>
<p>要问清线路断开后是自动重拨到同一段还是可能换段。自动重拨到同一段可以接受，换段就要有通知机制。切换策略方面，主备切换的判定条件是什么、切换需要多久、切换后出口是否同国同时区，三项都要有明确答案。</p>

<h2>四、地区与语言类参数</h2>
<p>这一组是「自洽性」参数，很多账号被关联不是因为出口不干净，而是因为出口、时区、语言三者互相矛盾。</p>

<h3>三件套必须对齐</h3>
<p>出口国家或城市、系统时区、浏览器语言。对齐的标准不是「大致对应」，而是能说出为什么：出口在法兰克福，时区用 Europe/Berlin，语言用 de-DE 或 en-US 都合理；出口在法兰克福而时区是 Asia/Shanghai，就明显不自洽。这一项检查不需要工具，手工看一遍配置即可，但最常被漏掉。</p>

<h3>城市级信息的处理</h3>
<p>出口城市和账号资料里的城市不必完全一致，但要在同一个时区、语言环境内。跨时区的组合（比如资料写柏林、出口在纽约）属于明显矛盾。如果服务商只能提供国家级选择，优先选人口多、出口密集的城市，避免小城市出口带来的低复用异常。</p>

<h2>五、容量与并发类参数</h2>
<p>这一组决定「能同时跑多少」。包括单线并发连接数、带宽上限、接口调用速率、以及单账号的请求节奏上限。</p>

<h3>三个容易踩的上限</h3>
<p>一是单线并发连接数，浏览器开多个标签页就会占用多条连接，标称 50 并发的线路，实际可用可能不到一半。二是带宽，家宽上行通常只有几十兆，同时上传大文件会拖慢所有会话。三是接口速率，批量开通时最容易撞上，通常限制在每分钟若干次，超了会返回 429。</p>

<h3>账号侧的节奏参数</h3>
<p>这一项没有标准值，原则是「像人」。请求间隔加随机抖动、避免整点集中、夜间降低频率。参考做法是间隔设在 90–180 秒随机，每天总量控制在一个自洽的范围内。节奏突变比节奏快更容易引起注意。</p>

<h3>参数的记录方式</h3>
<p>建议把所有参数写进一张配置表，每个环境一行，包含线路编号、出口段、时区、语言、分辨率、浏览器版本、并发上限。出问题时逐项对比，能快速定位是哪一项漂了。这张表也是交接时最有用的文档。</p>

<h2>六、常见问答</h2>
<h3>参数都对了，账号就不会被关联吗？</h3>
<p>答：不能保证。参数解决的是「不自相矛盾」，但账号行为、历史记录、资料完整度同样起作用。参数齐全只是把明显的矛盾排除掉，剩下的要靠正常使用和稳定节奏。</p>

<h3>浏览器语言设成英文会影响使用吗？</h3>
<p>答：会改变界面语言，但不影响功能。如果出口在欧洲而长期用中文界面，这个组合本身少见。建议按出口地区设首选语言，需要中文界面时把中文放到第二语言位，而不是反过来。</p>

<h3>单线并发数怎么测才准？</h3>
<p>答：用压测工具逐步加并发，观察第几个连接开始出现超时或重置，那个数字就是实际可用并发。标称值通常按理想条件给出，实际会低三到五成。长期跑建议只用标称值的一半。</p>

<h3>时区可以随时改吗？</h3>
<p>答：技术上可以，但不要频繁改。时区变化会被记录，一个号在两周内换三次时区，比一直用错时区更可疑。要改就一次改到位，然后长期不动，改完观察一段时间。</p>
